## 자동수집 실패

확인한 실행: https://github.com/ksg0694-ops/NetVisualizer/actions/runs/34966773540

- 메일 6건에서 파싱 및 process_attachment 결과 로그가 출력된 후 `supabase_http_400` 발생.
- 이 실행의 각 결과는 신규 삽입 0건이며, 시작일 이후 대상 거래가 모두 기존 중복으로 판별됐다. 따라서 이 실행의 실패를 곧바로 신규 거래 누락으로 해석할 수 없다. 전체 원장 완전성 검증은 별도다.
- `tools/banksalad_mail_sync.py`는 결과 전체를 완료 상태와 함께 `banksalad_sync_runs`에 upsert한다.
- 반환 결과의 `import_start_date`, `rows_eligible_incremental`, `rows_ignored_before_start`가 실제 DB 테이블에 없다. information_schema를 read_only 질의해 확인했다. 로컬 생성 마이그레이션에도 해당 열이 없다.
- 오류 본문을 버리고 HTTP 상태만 기록하기 때문에 정확한 서버 오류 코드는 로그에 남지 않았다. 코드 실행 순서, 완료 전 결과 로그, 실제 스키마의 불일치가 완료 기록 실패를 설명한다. 존재하지 않는 열 요청의 400 오류는 [PostgREST 공식 오류 문서](https://docs.postgrest.org/en/v12/references/errors.html)의 동작과도 부합한다.
- 완료되지 않은 메일은 재시도 대상에 남아 불필요한 재처리가 반복될 수 있다.

권장 수정: 집계 열을 추가하는 명시적 마이그레이션과 전송 필드 계약 테스트를 함께 적용. 이 세 항목을 운영 이력에 보존할 필요가 없다면 저장 payload에서 제외하는 더 작은 대안도 가능하다. 비밀/거래 내용 없이 안전한 DB 오류 코드와 요청 대상만 남긴다. 수정 후 같은 메일의 중복 방지 및 완료 처리 검증을 거쳐 정상 실행을 확인한다. 이번 검토에서는 수정/재실행하지 않았다.

## 코드에서 확인한 설계 위험

- portfolioViews.js는 요약, 전략, 편집, 성과, 2단 종목 아코디언을 한 흐름에 렌더링한다. 조회와 수정의 역할을 분리할 여지가 크다.
- financeModel.js는 시세 연결 실패 시 저장 평가액으로 대체한다. 시세가 존재하면 날짜의 신선도와 무관하게 시장평가로 계산한다. 히트맵에서 최신/오래된 시세/수동 평가를 구분해야 한다.
- 총평가액은 전체 종목, 총손익은 평균단가와 현재가가 비교 가능한 종목만 포함한다. 금액 가중 손익 계산 가능 비중을 함께 보여야 한다.
- 외화 평균매입가와 현재가를 모두 현재 환율로 환산하므로 매입 당시 환율 대비 환차손익은 반영되지 않는다. 현재 returnPct는 동일 통화 가격 수익률이며 실제 원화 총수익률로 표시하면 안 된다. 수수료·배당·실현손익도 별도다.
- 숨김 기능에 남은 'MDD 방어 상태'는 실제 최대낙폭이 아니라 현금 비중이다. 새 화면에는 이 표현이나 현금 비중만으로 안정/위험을 단정하는 등급을 이어받지 않는다.

## 제안: 투자 현황을 읽는 순서

1. 상단 4개: 총평가액 / 비교 가능한 미실현 손익 / 상위 3종목 비중 / 시세·손익 계산 가능 비중. 기준 시각을 짧게 표시.
2. 중앙: 보유금액 가중 트리맵(사용자가 말한 종목 히트맵). 전략 → 종목으로 묶고 계좌 필터 제공.
3. 하단: 손익 기여금액 순위와 보유 목록. 편집은 종목 선택 후 상세 패널 안에서 수행.

### 히트맵 규칙

| 표현 | 의미 | 안전장치 |
|---|---|---|
| 면적 | 원화 평가금액 / 선택 범위 총평가금액 | 순자산·부채를 면적에 섞지 않음; 평가 출처 표시 |
| 기본 색 | 평균매입가 대비 가격 수익률 | 환율 효과 제외를 명시; 손익금액과 혼동 금지 |
| 그룹 | 전략 → 종목 | 같은 종목의 여러 계좌 보유를 합칠 때 원가 가중 계산; 통화/시장 구분 |
| 라벨 | 종목명, 비중, +/- 수익률 | 색만으로 구분하지 않음; 색상 범례 고정 |
| 결측 | 회색 + 계산 불가 사유 | 0%로 채우지 않음; 오래된 시세는 별도 상태 |
| 선택 | 탭/클릭 후 상세 | 작은 칸은 확대·목록 대체; hover 필수 금지 |

보조 색상 모드는 '목표비중 대비 차이(%p)'가 유용하다. 목표비중이 실제로 설정된 경우에만 사용한다. '오늘 등락'은 직전 거래일 종가, 기준일, 시장 시간대, 시세 이력 연결이 검증된 뒤 추가한다. 서로 다른 지표의 색상 범례는 분리한다.

모바일은 전략별 요약 → 종목 확대를 기본 탐색으로 하고, 동일 데이터의 정렬 목록을 항상 제공한다. 작은 종목의 면적을 임의로 부풀리지 않는다. 색상 강도는 극단값에 상한을 두더라도 실제 숫자는 유지한다.

## 단계와 검증

1. 수집 상태 기록 계약 수정 및 재실행 확인 (승인 후).
2. 평가/손익/비교가능 범위 정의를 순수 모델로 정리. UI와 데이터 접근 분리, 출처별 결측 규칙 고정.
3. 기존 탭을 보존하고 투자 Lab에서 합성 데이터 시안 검토. 계좌 중복 합산, 빈 데이터, 환율 누락, 오래된 시세, 큰 손익, 작은 종목 검증.
4. 합계 일치, 원가 가중 수익률, 면적 비중, 색상 범위, 모바일·키보드 접근성 확인 후 기존 화면과 비교해 채택.

차트별 중복 집계는 만들지 않고 하나의 view model을 히트맵·목록·요약이 공유한다. 계산 계약과 변경 위치를 짧은 문서 및 테스트로 유지하면 후속 변경 시 재탐색/토큰 사용을 줄일 수 있다.

# Update 1.04 상세 설계

## 1. 포트폴리오 분류 모델

`asset_class`와 CFO 목적 그룹은 자금의 용도를 나타내며 그대로 유지한다. `strategy_tag`는 보유종목을 운용하는 이유를 나타내는 별도 축으로 사용한다.

```text
보유종목
 ├─ 목적: 운영 / 안전 / 투자 / 주거 / 연금
 └─ 전략: 현금대기 / 원자재 / 배당주 / 가상화폐 / 금융주 / AI(반도체)
```

연금계좌의 ETF도 계좌 목적은 연금으로 유지하고, ETF 자체는 여섯 전략 중 하나로 분류한다.

## 2. 전략 보드 상호작용

전략 보드는 여섯 개 고정 칸과 보유자산 카드로 구성한다.

1. 데스크톱 사용자는 카드를 잡아 다른 전략 칸으로 이동한다.
2. 모바일·키보드 사용자는 카드의 전략 선택 메뉴를 사용한다.
3. 화면 상태를 먼저 변경한다.
4. Supabase `portfolios.strategy_tag` 저장에 성공하면 최신 포트폴리오를 다시 불러온다.
5. 저장 실패 시 이전 전략으로 되돌리고 오류를 알린다.

카드는 원화 평가액 내림차순으로 표시한다. 전략 칸 머리에는 합계 평가액, 전체 대비 비중, 보유 개수를 표시한다.

## 3. 선제 분류 규칙

우선순위는 사용자가 저장한 새 전략 태그, 명확한 상품명·티커 규칙, 기본 주식 분류 순이다.

- 현금대기: MMF, 단기·중장기 미국채 ETF, 현금성 상품
- 원자재: 금·귀금속·원자재 ETF, 원자재 민감 종목
- 배당주: 배당·리츠·인컴·밸류업 종목
- 가상화폐: 가상화폐 지수·BTC·ETH 관련 상품
- 금융주: 은행·보험·증권·금융지주
- AI(반도체): AI·반도체·전력 인프라·성장형 지수 상품

기존 `index`, `growth`, `pension`, `other` 태그는 새 규칙으로 다시 계산한다.

## 4. 기능 비활성화

`APP_FEATURE_FLAGS`를 단일 기준으로 사용한다.

| 기능 | 상태 | 보존 범위 |
|---|---|---|
| 건강 | 비활성 | 기존 화면과 데이터 테이블 보존 |
| Quant 전략 구조 | 비활성 | 기존 계산·저장 함수 보존 |
| MDD 방어 상태 | 비활성 | 기존 계산 함수 보존 |
| 원화 평가 기준 카드 | 비활성 | 현재가·환율·원화 평가 계산 보존 |

비활성화된 건강 경로로 접근하면 생활 홈으로 이동한다.

## 5. 3년 단기 Roadmap

현재 기준월 다음 달부터 36개월을 계산한다.

- 월급: 관찰 기간 중 가장 낮은 월급
- 연봉: 기준 월급을 `1.5/20`으로 보고 역산
- 상여: 설날·추석 월에 각각 연봉의 `1/20`
- 자산 증가: 월 예상 수입 × 관찰된 저축+잔여 중앙비율
- 체크포인트: 12개월, 24개월, 36개월

장기 목표의 기존 예측 함수와 동일한 입력을 사용해 그래프와 Roadmap 숫자가 어긋나지 않게 한다.

## 6. 할 일 UX

- 상태 필터는 열림·완료·전체만 유지한다.
- 영역 필터는 버튼 묶음에서 단일 선택 메뉴로 변경한다.
- 목록에는 제목·영역·스텝 진행률만 표시한다.
- 날짜 입력·표시·오늘 마감·기한 지남 계산을 제거한다.
- DB의 `due_date`는 기존 스키마 호환값으로만 유지하고 사용자 경험에는 사용하지 않는다.
- 스텝 편집값은 줄바꿈 문자열이 아니라 `{ id, title, done, createdAt }[]` JSON으로 유지한다.
- 스텝 입력 단계부터 순서 변경과 개별 완료를 제공한다.

## 7. 검증

- 새 전략 여섯 개 외의 값이 `portfolios.strategy_tag`에 남지 않는다.
- 드래그와 선택 메뉴가 동일한 저장 함수를 사용한다.
- 전략 합계가 보드 대상 자산 합계와 일치한다.
- 36개월 체크포인트가 동일 월별 예측값의 12·24·36번째 값과 일치한다.
- 할 일 상세내역과 날짜가 목록 DOM에 존재하지 않는다.
- 스텝 완료 상태가 편집 저장 후 유지된다.

# Supabase 거래 전체조회 설계

## 조회 방식

- 페이지 크기: 1,000행
- 범위: `0-999`, `1000-1999`, ...
- 거래 테이블에만 페이지 크기를 선언하고, 각 페이지에서 기존 select와 order 조건을 동일하게 적용한다.
- 날짜와 거래 ID를 함께 정렬해 페이지 경계를 안정적으로 유지한다.
- 반환 행이 페이지 크기보다 작으면 종료한다.
- 페이지 중 오류가 발생하면 필수 테이블은 실패 처리하고 optional table은 기존 방식대로 건너뛴다.

## 안전장치

- 페이지별 결과를 합친 뒤 기존 normalize 함수를 한 번 적용한다.
- 저장·삭제 API는 변경하지 않는다.
- 인증과 RLS 정책은 변경하지 않는다.
- 테스트 클라이언트가 실제 Supabase의 `range(from, to)` 동작을 재현하도록 한다.

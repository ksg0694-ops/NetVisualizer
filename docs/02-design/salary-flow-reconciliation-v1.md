# 급여기간 정산 원장 v1 설계

## 목적

월급일 주변의 내부 이체를 개별 거래가 아니라 하나의 자금 흐름으로 묶는다. 중간 계좌를 거치는 이체는 순액만 월급 배분에 반영하고, 직접 관측한 값과 추정한 값을 구분한다.

## 모듈 경계

- `salaryFlowReconciliation.ts`: 내부 이체 매칭, 목적지별 순액, 근거 상태 계산
- `cashFlowAdapter.ts`: 전체 수입·지출 요약과 정산 결과 연결
- `graphBuilder.ts`: 정산된 배분 금액을 그래프 노드와 엣지로 변환

## 거래 매칭

급여 시작일부터 3일 이내의 `내계좌이체`와 `저축` 거래를 대상으로 한다.

1. 같은 날짜와 같은 절대금액의 출금·입금을 찾는다.
2. 시간이 있으면 15분 이내에서 가장 가까운 거래를 선택한다.
3. 시간이 없으면 원본 거래 순서가 가장 가까운 쌍을 선택한다.
4. 한 거래는 한 번만 사용한다.

매칭 결과에는 날짜, 금액, 출발 계좌, 도착 계좌, 양쪽 거래 키를 남긴다.

## 목적지 계산

| 목적지 | 계산 방식 | 상태 |
| --- | --- | --- |
| 월급 | 급여·월급 수입 합계 | 관측 |
| 청년도약계좌 | 청년·도약 출금 행만 합계 | 관측 |
| 연금저축펀드 | 월급일 부근의 짝 없는 10만원 출금 | 추정 |
| 신용대출 이자 | 상환 중 전세가 아닌 지출 | 관측 |
| 전세대출 | 상환 중 전세 지출 | 관측 |
| 생활비통장 순유입 | 월급통장→생활비통장 - 생활비통장→월급통장 | 관측 |
| 원화 발행어음 | 짝 없는 월급통장 내부 이체의 순출금 | 추정 |
| 월급통장 잔존액 | 월급 - 확정 배분 - 생활비 순유입 - 발행어음 | 추정 |

생활비 그래프 노드는 월급통장 잔존액과 생활비통장 순유입을 합친다.

## 근거 상태

- `observed`: 거래에서 직접 확인
- `inferred`: 거래 쌍 또는 금액 보존식으로 계산
- `target`: 실제 발행어음 근거가 없을 때 기존 목표 규칙 사용
- `missing`: 해당 거래를 확인하지 못함

## 폴백

짝 없는 월급통장 이체에서 발행어음 근거를 찾지 못하면 기존 규칙을 유지한다.

- 월급통장 목표 50만원
- 생활비통장 목표 50만원
- 남은 월급은 원화 발행어음

진행 중 급여기간처럼 데이터가 불완전할 때 실제값을 단정하지 않기 위한 동작이다.

## 보존 조건

다음 합계는 월급과 같아야 한다.

`생활비 + 청년도약계좌 + 연금저축펀드 + 원화 발행어음 + 신용대출 이자 + 전세대출`

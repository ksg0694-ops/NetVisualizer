# Update 1.04.03 성능·배포 기반 정리 계획

## 목표

- 최신 `origin/main`과 실제 GitHub Pages 배포본을 동일한 기준으로 맞춘다.
- 첫 화면에서 필요하지 않은 런타임과 숨은 화면 렌더를 제거해 체감 반응 속도를 높인다.
- 이후 수정 요청은 검증 후 `main`에 반영하고 실제 배포 버전까지 확인할 수 있게 한다.

## 진단 기준

- 배포본과 `origin/main`의 Service Worker 캐시 버전이 같은지 확인한다.
- 초기 HTML이 불필요한 PPT 생성기를 선로딩하는지 확인한다.
- 화면 전환 시 같은 기능의 `render()`가 중복 호출되는지 확인한다.
- 대시보드 갱신이 숨겨진 Monthly Report, 현금흐름, 포트폴리오 차트까지 생성하는지 확인한다.

## 범위

- 데이터 모델과 Supabase 스키마는 변경하지 않는다.
- 초기 스크립트 로딩, 화면별 렌더 라우팅, 정적 배포 검증 도구만 정리한다.
- 기존 GitHub Pages의 `main` 루트 자동 배포 방식을 유지한다.

## 완료 조건

- 전체 `npm run check`가 통과한다.
- Todo, 학습 아카이브, Monthly Report 화면을 전환해 단일 렌더 경로가 정상 동작한다.
- 로컬 캐시 버전과 배포 캐시 버전을 비교하는 명령이 제공된다.
- 실제 GitHub Pages가 새 캐시 버전을 제공하는지 확인한다.

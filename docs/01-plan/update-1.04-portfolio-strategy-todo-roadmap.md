# Update 1.04 구현 계획

## 목표

Update 1.04는 포트폴리오를 투자 전략 중심으로 재구성하고, 3년 단기 Roadmap과 할 일 입력 UX를 정리하는 패치다. 기존 자산군 분류와 평가 계산은 유지하되 화면에서 중복되거나 아직 사용하지 않는 기능은 되돌릴 수 있게 비활성화한다.

## 범위

### 1. 포트폴리오 전략별 분류

투자 전략은 아래 여섯 개로 고정한다.

| 키 | 표시명 | 1차 자동 분류 기준 |
|---|---|---|
| `cash` | 현금대기 | 현금, 예수금, CMA, RP, 대기자금 |
| `commodity` | 원자재 | 금, 은, 원유, 구리, 원자재 ETF |
| `dividend` | 배당주 | 배당주, 리츠, 인컴, SCHD |
| `crypto` | 가상화폐 | BTC, ETH, 가상화폐 관련 상품 |
| `financial` | 금융주 | 은행, 보험, 증권, 카드, 금융지주 |
| `ai_semiconductor` | AI(반도체) | AI, 반도체, 데이터센터, 관련 ETF |

- 운영자산·안전자산·투자자산·주거자산·연금은 자산의 목적을 나타내는 기존 분류로 유지한다.
- 새 전략 분류는 자산 목적과 별개의 축으로 저장한다. 예를 들어 연금계좌 안의 반도체 ETF는 자산 목적이 `연금`, 투자 전략은 `AI(반도체)`가 된다.
- 자동 분류 결과가 확실하지 않은 자산은 임의로 다른 전략에 넣지 않고 검토 대상으로 표시한다.
- 현재 보유자산을 새 규칙으로 1차 분류한 뒤 사용자가 드래그하여 최종 확정한다.
- 전략 칸 내부에서는 원화 평가액이 큰 자산부터 정렬한다.

### 2. 드래그 이동

- 투자 상세 화면을 여섯 개 전략 칸으로 구성한다.
- 자산 카드를 다른 전략 칸에 놓으면 `portfolios.strategy_tag`만 갱신한다.
- 화면은 먼저 이동시키고 저장 실패 시 원래 위치로 되돌리며 오류 메시지를 표시한다.
- 마우스 드래그 외에 키보드와 모바일용 전략 선택 메뉴를 함께 제공한다.
- 전략 칸마다 합계 평가액, 전체 투자자산 대비 비중, 보유 개수를 표시한다.

### 3. 비활성화 항목

아래 항목은 코드와 데이터는 보존하고 화면 진입만 막는다.

- Quant 전략 구조
- MDD 방어 상태(현금 비중)
- 원화 평가 기준 설명 카드
- 건강 탭, 생활 홈의 건강 카드, 모바일 건강 메뉴

현재가·환율·원화 평가 계산 자체는 포트폴리오 정렬과 전략별 합계에 필요하므로 계속 실행한다. 비활성화 대상은 계산이 아니라 중복 설명 UI다. 건강 URL로 직접 진입하면 생활 홈으로 이동시킨다.

### 4. 단기 Roadmap 3년

- 장기 목표 화면에 현재 월부터 36개월까지의 단기 Roadmap을 추가한다.
- 기존 장기 목표 그래프의 수입 추세 기반 예상값을 재사용한다.
- 1년차, 2년차, 3년차 말의 예상 순자산과 연간 증가액을 표시한다.
- 각 연도에는 사용자가 정한 핵심 목표와 완료 상태를 연결할 수 있게 한다.
- 임의의 직선 증가율이나 기존 1.45억·8억·30억 고정 구간은 사용하지 않는다.

### 5. 할 일 UX

- 영역 필터와 입력 영역 선택은 나열형 버튼 대신 단일 `<select>`로 변경한다.
- 목록 카드에는 제목, 영역, 스텝 진행률만 표시한다. 상세내역은 상세 화면에서만 표시한다.
- 날짜 입력·목록 날짜·오늘/지연 계산을 UI에서 제거한다.
- 기존 `due_date` DB 컬럼은 호환성을 위해 nullable 상태로 유지하되 신규 저장과 정렬에는 사용하지 않는다.
- 스텝 입력 행마다 순서 이동 손잡이와 완료 체크박스를 함께 제공한다.
- 이미 구현된 저장 후 스텝 순서 변경과 개별 완료 기능을 그대로 재사용한다.
- 스텝 편집 중에도 완료 상태를 잃지 않도록 제목 문자열이 아니라 `{ id, title, done }` 구조를 유지한다.

## 구현 순서

1. 기능 플래그와 새 전략 메타데이터를 추가한다.
2. 기존 `strategy_tag`를 새 여섯 전략으로 변환하는 미리보기와 검토 목록을 만든다.
3. 전략 보드와 드래그 저장·실패 복구·모바일 선택 기능을 구현한다.
4. 포트폴리오의 세 중복 블록과 건강 진입점을 비활성화한다.
5. 수입 추세 기반 36개월 Roadmap을 구현한다.
6. 할 일 영역 선택, 목록 정보, 날짜, 스텝 편집 UX를 수정한다.
7. 데스크톱·모바일·키보드 조작과 Supabase 저장 정합성을 검증한다.

## 데이터 변경 원칙

- 평균매입단가, 현재가, 환율, 원화 평가액은 변경하지 않는다.
- 기존 전략 태그는 일괄 덮어쓰기 전에 변환 결과를 검증한다.
- 사용자가 드래그로 확정한 분류는 자동 추론보다 우선한다.
- UI 비활성화는 데이터 삭제나 테이블 삭제를 수반하지 않는다.

## 완료 조건

- 23개 보유자산이 여섯 전략 중 하나 또는 명시적 검토 상태로 보인다.
- 드래그 및 선택 메뉴로 전략을 옮긴 뒤 새로고침해도 위치가 유지된다.
- 전략별 합계와 전체 원화 평가액이 기존 평가 합계와 일치한다.
- 36개월 예상값이 장기 목표의 수입 추세 계산과 동일한 입력을 사용한다.
- 할 일 목록에 상세내역과 날짜가 노출되지 않는다.
- 스텝의 순서와 개별 완료 상태가 편집·저장·새로고침 후에도 유지된다.
- 비활성화 항목으로 직접 진입하거나 호출해도 빈 화면이나 오류가 발생하지 않는다.
